# Expectations

| Claim | Disproved by | Where to look |
|---|---|---|
| Meta's published Quest app pairs with a build of this source and plays a clip. | A failed pairing. | A Quest headset and a built app |
| USB preview works for Quest with no network. | No connection. | A Quest headset over USB, network off |
| `SECURITY.md` lists every destination a running build contacts, on macOS and Windows, including whether the Windows spell-check dictionary download happens. | A traffic capture showing another host. | Traffic capture of a running build on each platform |
| Every link on the Resources page opens the documentation it names. Checked by research on 2026-11-12, except the FMOD anchor `#haptics-instrument` and the Wwise page, which did not load for it. The PlayStation entry says Sony publishes no public DualSense haptics documentation. The lint does not open web links. | A dead link, or a page about something else. | Open each link in `docs/design-and-integration/resources.md`. |
| A `.wav` export from Haptics Studio plays as haptics on a DualSense controller and feels like the clip, although it renders through the only actuator profile, `meta_quest_pro`. `docs/design-and-integration/resources.md` says it is untested. | No vibration, or a feel that does not match the clip. | A DualSense controller playing a `.wav` export through the platform's PCM haptics path |
| A link to a component folder with an anchor, such as `../main#application-data` in `docs/building.md`, opens the folder on GitHub and scrolls to that heading of its README. | The page opens at the top of the folder, or as a missing page. | Open `docs/building.md` on GitHub and follow its Application Data link. |
| The README banner shows `assets/logo-dark.png` in GitHub's dark theme and `assets/logo-light.png` in the light theme, 800 pixels wide. | Dark mode shows the light artwork or no image, light mode the dark artwork or no image, or a banner of another width. | The repository page on GitHub, in each theme |
| A packaged build shows the bird, not the circle, as the app icon on macOS and Windows and as the icon of `.haptic` and `.hasp` files; the iOS companion app shows it on the home screen. Once #47 adds the Icon Composer file, the icon fills its tile on macOS 26 and later with no grey border. | The circle or a blank icon; after #47, a grey tile around the bird on macOS 26. | A packaged build on macOS and on Windows, and an iOS build on a phone |
| The universal macOS app runs on an Intel Mac. Only its Apple silicon half has been started, from a local build. | A crash or no start on an Intel Mac. | The pre-release `.dmg` on an Intel Mac |
| An unsigned macOS app downloaded from the Releases page opens, at the latest after System Settings > Privacy & Security > Open Anyway. The workflow's app bundle carries no signature; only its executables carry the linker's ad-hoc signature. | macOS refuses it, for example as damaged, with no way to open it from System Settings. | The pre-release `.dmg`, downloaded in a browser, on a Mac |
| After the merge of #76, a maintainer can start the release workflow by hand on `integration/release-builds`: `gh workflow run release.yml --ref integration/release-builds -f tag=v2.5.0-beta.1`, and the run ends with a draft pre-release holding the three files. The `draft` job has not yet run on that branch. | `workflow release.yml not found`, no run, or a `draft` job that is skipped or fails. | The first run on that branch (#77) |
| Publishing the draft creates the tag at the commit the workflow built, and GitHub attaches a release attestation. | The tag points at another commit, or `gh release verify` finds no attestation. | `git ls-remote --tags origin` and `gh release verify v2.5.0-beta.1` after #77 publishes |
| The APK of a later pre-release installs over the one before on a phone, because the workflow raises `versionCode` with every run. | Android refuses the update. | Two pre-release APKs signed with the project's key (#64) on one phone |
| On a Mac without them, the steps in "Build from the Command Line" of `companion/android/README.md` install the JDK and the Android command-line tools and build both APKs. They were run only on a Mac that already had both installed. | A step that fails, or a missing APK. | A Mac without `openjdk@17` and `android-commandlinetools` |
| `./gradlew installDebug` puts the debug APK built without Android Studio on a phone, and the app pairs with the desktop app and plays a clip. | An install error, a crash at start, or no pairing. | A phone connected over USB with USB debugging on |
